# Stateless Clone API coverage

Upstream `stream/empty.rs`, `stream/pending.rs` and `future/pending.rs` each implement `Clone` for all T, without a `T: Clone` bound. Their clone bodies call the corresponding existing empty/pending factory; no item/output is stored or copied. Kotlin omitted all three concrete methods. This bounded manual consumer repair adds `EmptyStream<T>.clone()`, `PendingStream<T>.clone()` and `Pending<T>.clone()`, each delegating to its existing owning factory with the same concrete generic result. It leaves polling, hints, termination, names and all existing signatures untouched. No shared helper or substitute Clone type is introduced.

Original-file translations of stream/empty.rs and future/pending.rs succeeded into build/rust-kotlin-stateless-clone scratch. The immediately preceding stream/pending.rs translation is reused after verifying its source hash, rather than rerunning it. All three emitted outputs contain the constructor-based clone methods. Commands/source/binary/output hashes and copied prior provenance are retained. The output is structural comparison evidence, not compiled wholesale, and the recorded CLI binary is not attested as Iris's current build. No generator investigation/edit/rebuild or guard bypass occurred.

`cargo test --offline --manifest-path verification/stateless-clone-oracle/Cargo.toml --target-dir build/rust-kotlin-stateless-clone/rust-target` runs three groups against actual upstream APIs. The payload deliberately has no Clone/Copy/Debug/PartialEq implementation; an explicit `T: Clone` check applies to the wrapper, and concrete cloned return types retain `Option<NoClone>`. Each original and clone is checked before/after repeated polls, with a further clone after polling. Empty remains End, pending stream/future remain Pending, metadata stays exact, and the supplied wake counter stays zero. Rust pattern checks avoid accidentally requiring payload equality/debug traits.
